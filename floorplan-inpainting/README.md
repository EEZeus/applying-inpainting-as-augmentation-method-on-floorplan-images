# Floor-plan inpainting augmentation — Phases 1 and 2

Leakage-safe data preparation, a torchvision Mask R-CNN baseline, and local structure-preserving inpainting augmentation for the COCO room-instance dataset. Comparative M0–M3 training remains Phase 3.

## What is already prepared

- Audit verified: 60 images, 1,709 polygon annotations, 19 categories, no missing images.
- Exact duplicates removed by SHA-256 verification (source JPEGs are untouched): IDs `22`, `24`, `25`, and `26`.
- Clean COCO data: 56 images and 1,633 annotations.
- Project-aware split generated by seeded search; no project or image crosses partitions.
- Geometry statistics and all split/class manifests are generated under `outputs/`.
- All 19 categories remain model labels `1..19`; `0` is background.

Labor is confined to training and is excluded from quantitative augmentation claims. Werkstatt has four train instances and one test instance; any score is explicitly low-support. The chosen split favors valid class learning and rare-class test coverage over exact 70/15/15 sizes.

## Train and evaluate

Run a one-epoch end-to-end smoke test first:


Then run the configured 25-epoch baseline and test evaluation:

```bash
python scripts/train_baseline.py
python scripts/evaluate_baseline.py --checkpoint outputs/checkpoints/best.pth --split test
```

Training uses pretrained `maskrcnn_resnet50_fpn_v2`, native aspect-preserving resizing (`min_size=1024`, `max_size=1600`), AMP, conservative horizontal/photometric augmentation, and TensorBoard. The best checkpoint is selected by validation mask AP. Evaluation writes bbox/mask AP, AP50, AP75, per-class mask AP/AP50, test support, and the rare-class macro AP. It also writes up to 20 side-by-side GT/prediction images.

## Phase 2: unattended augmentation

The existing 56-image deduplicated dataset and 35/10/11 project-aware train/val/test split remain the source of truth. Generation scripts check those split files against the Phase 1 manifest and only open training images. Source data and baseline training code are untouched.

Activate `inpainting`, then install the additional pinned dependencies:

```bash
python -m pip install -r requirements.txt
python scripts/cache_inpainting_model.py
pytest -q
```

Weights are downloaded into `data/cache/huggingface`; inference runs locally. No floor-plan image is uploaded. The backend uses the [Stable Diffusion inpainting checkpoint](https://huggingface.co/stable-diffusion-v1-5/stable-diffusion-inpainting), retains its safety checker, and records the exact downloaded revision. The configured checkpoint supplies fp16 safetensors; CPU falls back to float32 execution. CUDA is strongly recommended. Model/cache/device/dtype and prompts are configurable. Seeds reproduce an individual candidate on the same software/GPU stack; bitwise diffusion reproducibility across different GPU models is not promised.

Run everything without a human review step:

```bash
sbatch slurm/run_phase2.sbatch
```

This job generates A, creates contextual training crops, generates B, automatically integrates B samples passing the geometry and pixel-QC checks, validates the output datasets, and writes counts and sampling reports. It does not train Mask R-CNN. Generation errors get up to two automatic retries; persistent model/download/runtime errors cause a nonzero exit and rerunning resumes completed work. GPU scheduling itself remains subject to the cluster queue.

Individual commands are also available:

```bash
python scripts/inspect_safe_masks.py --limit 30
python scripts/generate_strategy_a.py --limit 1
python scripts/generate_strategy_a.py --retry-errors
python scripts/generate_rare_crops.py
python scripts/generate_strategy_b.py --plan-only
python scripts/generate_strategy_b.py --retry-errors
python scripts/report_augmentation.py
```

`slurm/generate_strategy_a.sbatch` and `slurm/generate_strategy_b.sbatch` request A100 partitions by default. Override the partition with `sbatch --partition=RTXA6000 ...` or another site partition. Both expose `NUM_WORKERS`, `RESOLUTION`, `MODEL_CACHE`, `OUTPUT_DIR`, `QA_DIR`, and `SMOKE_ONLY=1`. Their first candidate is a preflight and is reused on the full run. The original `generate_inpainting_a.py` and its SLURM entrypoint remain compatible.

## Mask safety and quality

Each target uses the existing polygon rasterizer. The erosion radius is `round(clamp(0.02 * min(bbox_width, bbox_height), 2, 12))`, applied with an elliptical kernel at original resolution. Otsu thresholding uses grayscale values inside the target room; a numeric `dark_threshold` can replace Otsu. A two-pixel dilation protects detected strokes. All other annotation masks are subtracted to protect overlaps. The default minimum mutable fraction is 0.20, with per-category overrides in `mask.min_mutable_fraction_by_category`.

The generation crop adds one bbox width/height on each side, clamps to the image, pads with white, and resizes to 512². Images use bicubic interpolation and masks use nearest-neighbor interpolation. Recorded crop bounds, padding, and size reconstruct the transform. After inverse mapping, a binary NumPy assignment copies generated pixels only where the original-resolution safe mask is true. PNG output is reopened and compared. Exact outside/boundary invariance is mandatory and cannot be disabled by config.

QC rejects empty/small masks, almost identical outputs, uniform or blank regions, and extreme increases in dark or saturated filling. Defaults and thresholds live in the augmentation YAML files. Metadata includes safe-area fraction, resolved dark threshold, pixel-change statistics, before/after white/dark/color fractions, generated-region deviation, runtime, prompts, seed, crop transform, model revision, and failure reason. These raster checks preserve existing protected pixels; they cannot certify the architectural meaning of newly generated pixels.

Seven-panel QA rows show original plan, source crop, room mask, safe mask, generated crop, amplified crop difference, and final plan. Class-stratified sheets contain up to 30 examples, including QC rejections when available. Raw generated crops are QA artifacts only.

## Outputs and experimental interpretation

Strategy A defaults to three variants for each of the 30 primary rare training instances: up to 90 attempts. Each full plan changes one target room. Accepted samples retain every source annotation field except the new IDs/image references. The full dataset includes byte-copied original training images and accepted PNGs:

- `data/augmented_a/full_images/`
- `data/augmented_a/instances_train_aug_a.json`
- `data/augmented_a/crops/images/`
- `data/augmented_a/crops/instances_train_aug_a_crops.json`
- `outputs/augmentation_a/{summary.json,class_counts.csv,sampling_weights.csv}`

The crop dataset includes one crop per real rare room plus one crop for the changed target in each accepted A sample. Every intersecting annotation is geometrically clipped with Shapely and translated/scaled into the padded 512² crop; areas and bboxes are recomputed. Crops include context (default 3× bbox extent, minimum 2.5× before image-boundary clipping). Use `python scripts/generate_rare_crops.py --real-only` to build the original-only crop baseline under `outputs/rare_crops/real`. Phase 3 should mix crop images with full plans.

Strategy B targets 12, 13, 15, and 16 by default. It screens training classes 1–10 against real target-class area, aspect ratio, width, height, and solidity ranges (p05–p95 expanded by 50%). It uses each source annotation at most once across targets. The total-class balancing target is `min(3 * real_count, 20)`; the candidate budget is that target minus real count. QC rejection can leave the result below the target; generation does not loop indefinitely to fill a quota.

Per the unattended policy, successful geometry and pixel-QC checks automatically admit B samples. Only the selected annotation's category changes; its polygon and all other annotations remain unchanged. No human approval is required. `outputs/augmentation_b/review.csv` is now an **automatic decision audit**, not a review gate. It records `decision_method=automatic_geometry_and_pixel_qc` and `semantic_correctness=unverified`. The generic diffusion model does not establish class correctness; B remains an experimental source of potential label noise and must be reported separately from A.

- `data/augmented_b/candidates_review_only.json` contains QC-passing candidates (legacy diagnostic filename).
- `data/augmented_b/instances_train_aug_b.json` contains originals plus automatically accepted B samples.
- `instances_train_aug_b_approved.json` is a compatibility copy; “approved” means automatic QC, not human review.
- `outputs/augmentation_b/{geometry_screening.json,review.csv,review_summary.json,summary.json}` records selection, automatic acceptance, and failures.

`build_strategy_b_review.py` and `apply_strategy_b_review.py` are compatibility commands to rebuild the automatic audit/integration; neither waits for edited statuses. Sample identity, source hashes, and output hashes are verified. Counts label only the deliberately regenerated A target as a **synthetic appearance occurrence**; unchanged annotations duplicated as full-plan context are reported separately. Only converted B targets count as **new synthetic B room instances**. These counts do not imply new independent geometries for A or verified semantics for B. Classes 17–18 are exploratory; Labor is excluded from generation defaults and primary quantitative claims.

## Rare-aware sampling for Phase 3

`src/augmentation/rare_sampling.py` computes `min(5, 1 + 2 * sum(n_ic / sqrt(real_train_count_c)))` by default. The real counts come only from original training annotations, not the augmented distribution. It supports inverse, inverse-square-root, or uniform class weights and uniform image sampling. Weights stay in `[1, max_image_weight]`, so the maximum probability is bounded by `cap / (N - 1 + cap)`. The CSV reports each image's classes, count, base/final weights, and normalized probability.

```python
from src.augmentation.rare_sampling import sampling_weights, make_sampler

# Match the exact FloorplanCocoDataset image order when constructing the sampler.
weights, rows = sampling_weights(coco, real_train_coco, rare_ids, sampling_config,
                                image_ids=[im['id'] for im in dataset.images])
sampler = make_sampler(weights, seed=42)
```

Phase 3 uses this bounded weighting in E1, E3, E5, and E7. Load augmented COCO with `image_dir` equal to the JSON's parent directory; it contains all 19 categories. The Phase 3 loader traces every augmented image back to the frozen training IDs and rejects validation/test provenance rather than filtering out synthetic IDs.

## Resume and validation

Candidates receive stable annotation/variant keys, seeds, filenames, image IDs, and annotation-ID blocks. A run manifest hashes the full source COCO, training image contents, candidate plan, prompts, masks, and generation/QC settings. A changed experiment must use a new output directory. Generation is ordered on one GPU; CPU workers prefetch a bounded number of preparations. An exclusive output lock prevents concurrent writers. Images/JSON are atomically replaced; append-only metadata records are flushed. A crash-truncated metadata row is retried using the same ID. Accepted files with missing/mismatched hashes are repaired; completed rejections are skipped and transient failures require `--retry-errors` (enabled by the unattended job).

```bash
python scripts/validate_augmented_dataset.py data/augmented_a/instances_train_aug_a.json
python scripts/validate_augmented_dataset.py data/augmented_a/crops/instances_train_aug_a_crops.json
python scripts/validate_augmented_dataset.py data/augmented_b/instances_train_aug_b.json
```

Tests use a clearly labeled fake backend only in temporary test directories; fake samples never enter the real augmentation datasets. Tests cover masks, PNG invariance, crop clipping, annotation preservation, generation seeds/resume, train-only reads, unique IDs, COCO validation, bounded sampling, and automatic B admission. Actual GPU results are reported in generated summary files; absent files do not indicate completed inference.

## Class-agnostic baseline

The class-agnostic dataset is a second view of the deduplicated Phase 1 COCO data. It preserves all 56 image records, 1,633 annotation IDs, polygons, bboxes, areas, and the frozen 35/10/11 split; every annotation receives foreground category `1` (`room`). The Mask R-CNN therefore uses two model classes: background `0` and room `1`. The multiclass dataset and its outputs remain unchanged.

```bash
python scripts/create_class_agnostic_dataset.py

# Optional interactive smoke run
python scripts/train_baseline.py \
  --dataset-config configs/dataset_agnostic.yaml \
  --model-config configs/baseline_agnostic.yaml \
  --epochs 1

# Full cluster train and evaluation
sbatch slurm/train_baseline_agnostic.sbatch
sbatch --dependency=afterok:<TRAIN_JOB_ID> slurm/evaluate_baseline_agnostic.sbatch

# Or run both stages unattended in one allocation
sbatch slurm/train_evaluate_baseline_agnostic.sbatch
```

The agnostic experiment writes checkpoints, TensorBoard logs, metrics, and predictions to `outputs/checkpoints_agnostic`, `outputs/logs_agnostic`, `outputs/metrics_agnostic`, and `outputs/figures/predictions_agnostic`. Evaluation reports ordinary COCO bbox/mask AP, AP50, and AP75 for the single `room` category as well as `class_agnostic_mask_AP`; rare-class macro AP does not apply to this view.

## Phase 3 controlled experiments

Phase 3 implements E0–E7 in `configs/experiments/`. Every configuration declares both a multiclass and a class-agnostic track. The two tracks use the unchanged project-aware 35/10/11 split, the Phase 1 Mask R-CNN and optimization settings, independent pretrained initialization, seed 42, and exactly 35 optimizer steps per epoch. Augmented datasets are used only for training; validation and test always use the original held-out images and annotations. In the agnostic track, model labels are mapped to `room=1` at load time while original categories remain available solely for exposure attribution.

Run one smoke epoch; the full job can later continue the same run with `--resume`:

```bash
python scripts/run_experiment.py \
  --config configs/experiments/e0_original.yaml \
  --track multiclass --seed 42 --epochs 1
```

Submit all 16 single-seed jobs (E0–E7 × multiclass/agnostic) and the dependent report with one command:

```bash
bash scripts/submit_phase3.sh
```

Use `bash scripts/submit_phase3.sh --with-extra-seeds` to submit the complete unattended chain: seed-42 matrix, interim report, automatically selected E0/E1/best-A/best-B runs for seeds 123 and 2026, and final report. No manual method selection or QA decision is required.

Each job is restartable with `--resume`; its configuration fingerprint must match. Per-run outputs live at `outputs/experiments/<track>/<id>/seed_<seed>/` and include best/last checkpoints, training history, test metrics, prediction panels, and `class_exposure_by_epoch.csv`. The sampler holds every method to the same optimizer-step budget. E4/E5 draw full plans with probability 0.6 and rare-centered crops with probability 0.4; E5 applies bounded rare weighting within each source group so crops are not accidentally weighted twice.

After the seed-42 matrix completes, extra seeds can be launched automatically. The helper selects the best completed Strategy A and Strategy B variant independently for each track:

```bash
EXTRA=$(sbatch --parsable slurm/run_phase3_extra_seeds.sbatch)
sbatch --dependency="afterany:$EXTRA" slurm/report_phase3.sbatch
```

Regenerate tables and figures at any time with `python scripts/report_phase3.py`. Before experiments finish, missing cells are emitted as `NA`, never inferred. Final multiclass tables are written to `outputs/final/experiment_summary.csv`, `per_class_results.csv`, `class_exposure_summary.csv`, `augmentation_statistics.csv`, `seed_summary.csv`, and `result_summary.md`; `experiment_summary_agnostic.csv` provides the matched category-independent comparison. Rare AP/AP50 is defined only for multiclass classes 11–16 with test support. The agnostic comparison uses overall room mask/bbox AP, AP50, and AP75, while retaining original-category exposure diagnostics.

## Strategy C: exemplar-guided rare-room inpainting

Strategy C is an isolated follow-up to E0-E7. It transfers pixels from a real
rare training room into a geometry-compatible frequent-room polygon, preserves
the target boundary and surrounding plan, and uses diffusion inpainting only for
seams and uncovered interior. Direct copy-paste (E8) and deterministic feather
blending (E9) control for the primary inpainting treatment (E10); E11 combines
E10 data with bounded rare-aware sampling.

No Strategy A/B data, Phase 3 checkpoint, or `outputs/final` report is modified.
Strategy C uses `data/augmented_c`, `outputs/experiments_c`, and
`outputs/final_c`. See [`docs/strategy_c.md`](docs/strategy_c.md) for the full
algorithm, QC rules, experiment interpretation, and reproduction procedure.

```bash
# Inspect all train-only donor/target pairings without a GPU.
python scripts/generate_strategy_c.py --plan-only --mode all

# Submit generation, E8-E11 for both tracks, and an isolated report.
bash scripts/submit_strategy_c.sh
```

## LoRA inpainting augmentation branch

The additional LoRA branch trains one shared SD 1.5 inpainting adapter from
room-centred **training-only** crops, oversamples/classically varies rare-room
crops, validates pretrained SD against LoRA with fixed cases, and creates
geometry-matched common-to-rare candidates. Geometry, pixel-quality, and exact
structural checks automatically admit or reject each candidate; there is no
human acceptance gate.

```bash
bash scripts/submit_lora_branch.sh
```

See [`docs/lora_inpainting_branch.md`](docs/lora_inpainting_branch.md) for the
algorithm, safety invariants, output inventory, scientific count distinctions,
and the 3–5 day execution protocol.

To evaluate multiple rare conversions within one synthetic plan, provide the
nominal common-room replacement percentage and random percentage-point jitter:

```bash
bash scripts/submit_lora_multiroom_experiments.sh 5 2
```

This builds the parameterized dataset and runs isolated E14/E15 uniform and
rare-weighted detector experiments. Only classes 1–10 can be sources and only
classes 11–16 can be targets; this constraint is validated in code.

## SAM 3 baseline

The independent SAM 3 baseline uses Meta's official trainer, text prompts from
the 19 COCO category names, instance-mask loss, and the unchanged 35/10/11
train/validation/test split. It reports COCO bbox and mask AP and does not alter
the Mask R-CNN or LoRA workflows.

Install the official repository and training environment once, accept the
gated `facebook/sam3` checkpoint license on Hugging Face, and authenticate with
`hf auth login`. By default the job expects the repository at
`/netscratch/espandar/sam3` and its environment at
`/netscratch/espandar/miniconda3/envs/sam3`; override `SAM3_ROOT` or `SAM3_ENV`
when submitting if needed. A local official checkpoint can be supplied through
`SAM3_CHECKPOINT` instead of downloading it on the compute node.

The current upstream package also requires `setuptools<82`, `einops`,
`pycocotools`, and `psutil` although they are not all declared as base runtime
dependencies.

```bash
sbatch --export=ALL,SAM3_ROOT=/path/to/sam3,SAM3_ENV=/path/to/sam3-env \
  slurm/train_evaluate_sam3.sbatch
```

Checkpoints, TensorBoard logs, validation/test metrics, and COCO prediction
JSON files are written below `outputs/sam3_baseline/`.
